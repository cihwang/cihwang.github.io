# 블로그 글쓰기 화면 설계 (velog식 에디터)

- 날짜: 2026-10-16
- 대상 저장소: `cihwang/cihwang.github.io` (GitHub Pages, 공개 저장소)

## 1. 왜 만드나

지금은 글 하나를 고치려면 PC에서 `posts/*.md`를 열어 마크다운으로 고치고, `python serve.py`로 미리 보고, `git commit`·`git push`까지 해야 한다. 폰에서는 아예 쓸 수 없다. Claude가 초안을 써 줘도 손보는 길이 같아서 불편하다.

목표는 **PC와 폰 어디서든, velog 글쓰기 화면처럼 쓰고·고치고·임시저장하고·출간하는 것**이다. 특히 "Claude가 쓴 초안도 내가 손으로 고치기 쉬워야" 한다.

## 2. 목표 · 하지 않을 것 · 실패로 보는 것

**목표**
- 사이트 안에서 새 글 쓰기, 임시저장, 이어 쓰기, 출간, 이미 올린 글 수정.
- PC: velog처럼 왼쪽 마크다운 쓰기 · 오른쪽 실시간 미리보기 (사용자가 시안을 보고 정함).
- 폰: 쓰기 / 미리보기 **탭** 전환, 서식 단추는 키보드 바로 위 (사용자가 시안 A를 고름).
- 사진: PC 붙여넣기·끌어다 놓기, 폰 사진첩에서 고르기 → 바로 올라가고 본문에 그림 줄이 들어간다 (사용자 요구).
- "출간하기"를 누르면 확인 단계 없이 바로 공개 (사용자가 정함). 출간 설정 칸(카테고리·날짜·URL)에서 누르는 출간하기가 그 최종 버튼이다.
- Claude가 쓴 초안도 임시글 목록에 떠서 같은 화면에서 고칠 수 있다(초안 저장소에 넣은 것, 5-8).
- 출간 전 초안과 사진은 남에게 보이지 않는다(5-8).
- 카테고리를 직접 만들고 이름을 바꿀 수 있다(5-9, 사용자 요구).
- **글·사진·카테고리를 바꾸는 모든 작업은 나만 할 수 있다**(사용자 요구, 5-7).

**하지 않을 것** (velog에는 있지만 이 블로그 화면에 쓰는 곳이 없음)
- 썸네일, 150자 소개, 시리즈, 태그(카테고리 하나로 대신), 비공개 출간(임시글이 그 역할).
- 보이는 대로 편집(WYSIWYG). 폰도 마크다운 + 미리보기 탭이다.
- 별도 서버·DB. 저장소는 GitHub 저장소 하나뿐이다.

**실패로 보는 것** (돌아가도 이러면 실패)
- 방문자가 글을 쓰거나 고칠 수 있다, 또는 방문자에게 글쓰기·수정 단추가 보인다.
- 미리보기와 실제 사이트에 올라간 모양이 다르다.
- 쓰던 내용이 사라진다(저장 실패를 조용히 넘기거나, 다른 기기에서 저장한 내용을 덮어쓴다).
- 기존 방식(파일을 직접 고치고 push)이 깨진다. 에디터가 만든 파일은 사람이 열어 고치기 쉬운 평범한 마크다운이어야 한다.

## 3. 현재 구조 (바꾸지 않는 전제)

- 글 원본: `posts/**/*.md`. 맨 위 `---` 사이 `title`(필수), `category`(`site.json`의 `글`·`공부`·`만든 것`·`취향` 중 하나, 필수), `date`(YYYY-MM-DD), `slug`, `draft`. 파일 규칙은 `build.js` 머리 주석과 `posts/_글쓰기-도움말.md`.
- 사진: `media/`에 두고 글에서는 `![설명](../media/파일)`.
- 배포: `main`에 push하면 `.github/workflows/deploy.yml`이 `node build.js`(초안 제외)로 `posts.json`을 만들고 Pages에 올린다. 약 25~30초 걸린다. `posts.json`은 `.gitignore`.
- 마크다운 → HTML: `build.js`의 `marked` 설정(highlight.js, 각주, 제목 id, KaTeX, 이모지, 그림 문법 하나로 사진·영상·유튜브). 버전은 `package.json`에 고정.
- 화면: `index.html` + `wheel.js`(휠·라우팅 `#/카테고리/slug`) + `help.js`(로컬 전용 `?` 도움말) + `sky.js`(테마). 글꼴 Pretendard · D2Coding.
- 저장소는 **공개**다. `draft: true` 글은 사이트에는 안 나오지만 GitHub 저장소에서는 누구나 읽을 수 있다.

## 5. 화면과 동작

velog(오픈소스 `velopert/velog-client`)에서 확인한 구성을 이 블로그 항목으로 옮긴다.

### 5-1. 글쓰기 화면
- 위: 제목 칸("제목을 입력하세요"), 카테고리 고르기(알약 4개), 서식 단추 `H2 H3 H4 | B I S | 인용 링크 사진 코드`. 본문에서 `#` 하나는 글 제목이 쓰고 있어서 H1 단추는 없다(`_글쓰기-도움말.md` 3절).
- 본문: 마크다운 쓰기 칸. 빈 칸 안내 문구는 velog와 같은 결("이야기를 적어 보세요…").
- 미리보기: 실제 글 화면과 같은 스타일(`.post-title`, `.post-body` 규칙)로, 쓰는 대로 바뀐다.
- 아래 막대: `← 나가기` · 마지막 저장 시각("저장됨 · 14:32") · `임시저장` · `출간하기`. 이미 올린 글을 고칠 때는 `출간하기`가 `수정하기`가 된다.
- 단축키: `Ctrl/Cmd+S` = 임시저장(velog `useSaveHotKey`와 같음). 서식 단추에도 흔한 단축키(`Ctrl+B`, `Ctrl+I`)를 붙인다.
- 문법 도움말: 기존 `posts/_글쓰기-도움말.md` 내용을 에디터 안에서도 열어 볼 수 있다.

### 5-2. 출간 설정 (출간하기 / 수정하기를 누르면)
- 카테고리, 날짜(기본: 오늘), URL(slug, 기본: 제목에서 만든 값). 확인을 누르면 바로 공개.
- 이미 공개된 글의 URL을 바꾸면 예전 링크가 끊긴다고 알려 준다.
- 같은 카테고리에 같은 slug가 있으면 막는다(`build.js`의 겹침 검사와 같은 규칙).

### 5-3. 임시글 목록
- 초안 저장소(5-8)의 글을 모두 보여 준다. 에디터로 저장한 글이든 Claude가 넣은 초안이든 구분 없이 보여 주고, 공개된 글을 고치는 중인 것은 "고치는 중"으로 표시한다. 제목 · 카테고리 · 마지막 수정 시각, `이어 쓰기`, `삭제`.
- 블로그 저장소에 남아 있는 `draft: true` 파일(예: 지금 있는 `posts/2026-10-13-agentforce-coworker.md`)도 "공개 저장소에 있음" 표시와 함께 보여 준다. 이어 쓰면 초안 저장소로 옮길지 묻는다.

### 5-4. 이미 올린 글 수정
- 글 화면에, 이 기기에서 로그인한 나에게만 `수정` 단추가 보인다. 누르면 그 글의 원본 `.md`를 열어 같은 글쓰기 화면으로.
- 글 삭제도 여기서 할 수 있다(확인을 한 번 묻는다).

### 5-5. 저장
- **자동 저장(기기 안):** 쓰다 멈추고 10초가 지나면 이 기기에 저장한다(velog는 10초 뒤 서버 임시저장. 여기서는 커밋이 쌓이지 않게 기기 안에만 저장). 창을 닫았다 다시 열면 이어서 나온다.
- **임시저장(GitHub):** 버튼이나 `Ctrl+S`. 초안 저장소(5-8)에 기록한다. 그래서 다른 기기에서도 이어 쓸 수 있고, 남에게는 보이지 않는다.
- **출간:** 블로그 저장소 `posts/`에 `draft` 줄 없이 기록한다. 그러면 배포가 돌아 약 30초~1분 뒤 사이트에 보인다. 그동안 "올리는 중" 상태를 보여 주고, 끝나면 그 글 주소로 데려간다. 출간이 끝난 뒤에만 초안 저장소의 그 초안을 지운다.
- **나가기 경고:** 이 기기에만 있고 GitHub에 올라가지 않은 변경이 있으면 나가기 전에 묻는다.
- **겹쳐 쓰기 방지:** 다른 기기에서 그 사이에 같은 글을 저장했으면 덮어쓰지 않고 알려 준다. 어느 쪽을 남길지 사용자가 고른다.
- **실패:** 저장·업로드가 실패하면 이유와 함께 알리고, 쓰던 내용은 기기 안 저장본으로 남긴다. 실패를 성공처럼 보이게 하지 않는다.

### 5-6. 사진
- 붙여넣기·끌어다 놓기·사진 단추(폰은 사진첩·카메라)로 고른다. 올라가는 동안 본문에 자리표시 줄을 둔다.
- 쓰는 동안에는 초안 저장소에 올린다(공개 전 사진이 새지 않게). 본문 줄은 처음부터 최종 모양 `![](../media/파일)`으로 넣고, 미리보기는 초안 저장소에서 토큰으로 받아 보여 준다. 출간할 때 그 사진들을 블로그 저장소 `media/`로 복사한다. 설명(대체 글)은 사용자가 채우게 비워 두되, 비어 있으면 출간 때 알려 준다(접근성).
- 큰 사진은 올리기 전에 가로 2000px 이하로 줄인다(`_글쓰기-도움말.md` 14절의 기준).

### 5-7. 나만 쓰기 (로그인)
- 기기마다 처음 한 번, **두 저장소 전용 GitHub 토큰**(fine-grained personal access token, 권한: 블로그 저장소와 초안 저장소의 Contents 읽기·쓰기만)을 넣는다. 토큰은 그 기기 브라우저에만 저장하고, 로그아웃하면 지운다. 토큰 만드는 법은 처음 화면에서 단계별로 안내한다.
- 토큰이 없는 기기(=방문자)에는 글쓰기·수정 단추가 생기지 않는다. 진짜 막는 건 GitHub 권한이다. 단추를 숨기는 건 보기 좋으라고 하는 것뿐이다.
- 글 쓰기·임시저장·출간·수정·삭제, 사진 올리기, 카테고리 만들기·이름 바꾸기 — 바꾸는 작업은 **모두** 이 토큰으로 GitHub에 쓰는 것으로만 이뤄진다. 사이트 자체에는 쓰는 길이 없다(정적 파일뿐). 그래서 토큰이 없으면 누구도 바꿀 수 없다. `write.html`은 누구나 열 수 있지만 토큰 없이는 로그인 화면에서 더 나가지 못한다.
- "GitHub로 로그인" 버튼은 토큰을 바꿔 줄 서버가 따로 있어야 해서 이번에는 하지 않는다. 필요해지면 토큰 입력 단계를 OAuth로 바꾸면 된다.

### 5-8. 초안 저장소 (비공개)
- 블로그 저장소(`cihwang/cihwang.github.io`)는 Pages 때문에 공개로 남는다. 그래서 초안·고치는 중인 내용·출간 전 사진은 **따로 만든 비공개 저장소**(무료, 이름은 사용자가 정함. 예: `cihwang/blog-drafts`)에 둔다.
- 초안 저장소 안의 모양은 블로그 저장소와 같다(`posts/…md`, `media/…`). 그래서 출간은 "같은 경로로 옮기기"가 되고, 사람이 저장소를 직접 열어 고치기도 쉽다.
- 저장소를 만드는 일과 토큰 발급은 사용자가 한다(GitHub 화면에서 한 번).
- Claude가 쓰는 초안도 앞으로는 이 초안 저장소에 넣는다. 그래야 임시글 목록에 뜨고 공개되지 않는다.
- 출간은 두 저장소에 걸친 여러 단계라 한 번에 끝나지 않을 수 있다. 순서는 ① 사진 복사 → ② 글 기록 → ③ 초안 삭제다. 중간에 실패하면 초안은 남겨 두고, 다시 누르면 이어서 끝낼 수 있게 한다(두 번 눌러도 사진·글이 겹치지 않게).

### 5-9. 카테고리 관리 (사용자 요구: "카테고리를 직접 생성하고 수정")
- 에디터 안 "카테고리 관리" 화면. 지금 카테고리 목록(휠 순서)과 각 카테고리의 글 수를 보여 준다.
- **만들기:** 이름을 넣으면 목록 맨 뒤(휠에서 마지막 구간)에 붙는다. 글이 없는 카테고리도 휠에 빈 구간으로 보인다(지금 `wheel.js`가 그렇게 그린다).
- **이름 바꾸기:** `site.json`의 그 자리 이름과, 그 카테고리에 속한 모든 글의 `category:` 줄을 블로그 저장소에 **한 커밋으로** 바꾼다. 초안 저장소에 있는 그 카테고리 초안도 같이 바꾼다. 바꾸기 전에 "글 N편이 옮겨지고, 예전 주소(`#/옛이름/…`)는 끊겨요"라고 알린다.
- **이름 규칙:** 앞뒤 공백 제거, 1~20자, `/ # ? %`와 맨 앞 `_`는 안 됨(주소와 파일 규칙에 걸림), 이미 있는 이름과 겹치면 안 됨.
- 카테고리 목록은 블로그 저장소의 `site.json`이 원본이다. 에디터는 사이트의 `posts.json`이 아니라 `site.json`을 읽는다. 방금 만든 카테고리가 배포 전에도 바로 보이게 하려는 것이다.
- **하지 않을 것(이번 범위 밖):** 카테고리 삭제, 순서 바꾸기. 요청에 없었다. 필요해지면 같은 화면에 더한다.

## 6. 만드는 방식 (Claude의 판단 — 사용자가 고른 것 아님)

- 에디터는 같은 사이트 안의 페이지(예: `#/write` 또는 별도 `write.html`)다. 저장·불러오기는 브라우저에서 바로 GitHub REST API(Contents API)를 부른다. 서버를 따로 두지 않는다.
- 임시저장은 초안 저장소에만 기록하므로 블로그 배포가 돌지 않는다. 출간·수정·삭제만 블로그 저장소에 커밋하고 배포를 돌린다.
- 미리보기는 `build.js`와 **같은 마크다운 설정**으로 그린다. 둘이 어긋나지 않게 설정을 한 곳에서 같이 쓰는 것이 좋다.
- 새 글 파일 이름은 지금 규칙대로 `posts/YYYY-MM-DD-<slug>.md`. 에디터가 만든 파일도 사람이 열어 바로 고칠 수 있는 평범한 마크다운이다(위 머리말 + 본문).
- 새 의존성(에디터용 라이브러리 등)이 필요하면 버전을 고정하고, 추가하기 전에 사용자에게 묻는다.
- **공개된 글을 고치는 중의 임시저장:** 공개본은 `수정하기`를 누를 때까지 그대로 둔다. 원본 파일에 `draft: true`를 붙이면 다음 배포 때 글이 사이트에서 사라지기 때문이다(2장 "쓰던 내용이 사라진다" 실패). 고치던 내용은 초안 저장소의 같은 경로(`posts/<원래 경로>`)에 저장한다. 그래서 다른 기기에서도 이어 쓸 수 있고 공개본은 영향을 받지 않는다. `수정하기`를 누르면 그 내용을 블로그 저장소 원본에 쓰고 초안 쪽은 지운다. 임시글 목록에는 "고치는 중"으로 함께 보여 준다.
- **미리보기 라이브러리는 직접 올린다(CDN에서 불러오지 않음):** 토큰이 있는 페이지에 외부 스크립트를 늘리지 않기 위해서다. `build.js`의 마크다운 설정을 브라우저와 Node가 같이 쓰는 모듈 하나로 빼고, 필요한 패키지 파일은 배포 때 `node_modules`에서 사이트로 복사해 import map으로 연결한다(`deploy.yml`의 파일 모으기 단계와 `serve.py`가 같이 바뀐다). 번들러는 넣지 않는다. 에디터 화면에서는 GoatCounter를 불러오지 않는다.
- **제목·카테고리 없이 임시저장:** 기기 안 자동 저장은 언제든 된다. GitHub 임시저장은 제목과 카테고리가 있어야 하고, 없으면 무엇을 채워야 하는지 알려 준다. `build.js`는 초안에도 제목·카테고리를 요구해서, 빈 초안 하나가 로컬 미리보기 전체를 깨뜨릴 수 있기 때문이다. `build.js` 검사는 바꾸지 않는다.
- **글 주소(slug)나 날짜를 바꿀 때:** 파일 이름도 새 규칙에 맞게 바꾼다. 글을 지워도 `media/`의 사진은 지우지 않는다(다른 글이 쓸 수 있다).

## 7. 만드는 사람에게 맡기는 것

- 에디터 주소(`#/write` 해시 라우트인지 별도 페이지인지), 쓰기 칸 구현(textarea인지 코드 에디터 라이브러리인지).
- 기기 안 저장의 형식과 키 이름, 사진 파일 이름 짓는 규칙.
- 겹쳐 쓰기 충돌 화면의 모양.
- 글 화면의 `수정` 단추 위치.
- 확인 방법: 이 저장소에는 자동 테스트가 없다. 저장·출간·충돌·실패 경로는 실제 브라우저에서 PC 폭과 폰 폭으로 확인한다. GitHub에 쓰는 동작은 연습용 글로 확인하고, 확인이 끝나면 지운다.

## 8. 알려진 한계

- 출간에서 사이트 반영까지 배포 시간(약 30초~1분)이 걸린다. velog처럼 즉시는 아니다.
- 출간된 글의 원본과 사진은 공개 저장소에 있으니 GitHub에서도 보인다(사이트에 공개한 것과 같은 내용).
- 이미 공개 저장소에 들어간 초안(`posts/2026-10-13-agentforce-coworker.md`, `media/agentforce-coworker/`)은 커밋 기록에 남는다. 초안 저장소로 옮겨도 과거 기록에서는 보인다.
- 토큰이 그 기기 브라우저에 저장된다. 사이트는 같은 출처에서 GoatCounter 스크립트(무결성 해시 고정)를 불러온다. 토큰 범위를 두 저장소의 Contents로 좁혀서, 새더라도 피해가 이 두 저장소를 넘지 않게 한다.
- 로컬 미리보기(`serve.py`)에서 에디터로 저장하면 GitHub에만 기록된다. 로컬 파일을 맞추려면 `git pull`이 필요하다.
